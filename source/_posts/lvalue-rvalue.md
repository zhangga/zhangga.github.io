# C++ 左值与右值详解：从表达式到右值引用、std::move

整理日期：2026-10-09。以 C++17 / C++20 为学习基线。

适合对象：已经接触拷贝构造、移动构造，但对 `&`、`&&`、左值和右值仍容易混淆的开发者。本文是一份可长期查阅的知识笔记，先建立直觉，再解释移动语义中的关键细节。首次阅读可按顺序学习；回顾时可直接查看速查表、常见问题与核心概念总结。

> 最重要的一句话：**左值和右值是表达式的分类，不是在判断它写在等号的哪一边，也不等同于变量的数据类型。**

## 1. 先从一个对象和一个计算结果开始

```cpp
int a = 10;
int b = 20;
```

再看下面这些表达式：

```cpp
a       // 左值
b       // 左值
10      // 右值
a + b   // 右值
```

### 1.1 表达式 a 表示一个具体对象

表达式 `a` 表示已经存在的那个 int 对象。你可以反复通过它访问同一个对象：

```cpp
a = 30;
std::cout << a;
```

因此，`a` 是左值表达式。

### 1.2 表达式 a + b 产生一个计算结果

```cpp
int c = a + b;
```

`a + b` 计算出一个值，用来初始化 `c`。它不是在表示原来的 `a` 或 `b`，而是在产生计算结果，因此这里是右值表达式。

可以先建立这样的直觉：

- 左值的常见情况是：“这里表示一个具体对象。”
- 右值的常见情况是：“这里产生了一个结果。”

这只是入门直觉，不是完整定义。后面会看到，右值中的 `std::move(a)` 仍然关联一个已有对象。

### 1.3 数据类型和值类别是两个维度

`a` 和 `a + b` 都具有 int 类型，但值类别不同：

| 表达式 | 类型 | 值类别 |
|---|---|---|
| `a` | int | 左值 |
| `a + b` | int | 纯右值，属于右值 |

类型说明“表达式涉及什么类型的数据”，值类别则参与决定引用如何绑定、重载如何选择等规则。两者都要看，不能只看类型。

## 2. 为什么不能根据等号左右判断

### 2.1 写在等号右边，也可以是左值

```cpp
a = b;
```

虽然 `b` 出现在等号右边，表达式 `b` 仍然是左值。它表示已经存在的对象 b。

“左值”和“右值”的名称不能直接当成现代 C++ 的判断公式。

### 2.2 不能修改，也可以是左值

```cpp
const int count = 10;

// count = 20; // 错误：不能修改 const 对象
```

表达式 `count` 仍然是左值，只是它不是可修改左值。

**左值不等于可以修改。** const 限定和值类别是不同维度。

### 2.3 不是普通变量名，也可以是左值

```cpp
int values[3]{};
int* p = &a;

values[0] = 42; // values[0] 表示一个具体数组元素
*p = 50;        // *p 表示指针指向的对象
```

这里 `values[0]` 和 `*p` 都是左值表达式。它们本身不是一个普通变量名，但仍表示具体对象。

因此，“有名字就是左值，没有名字就是右值”也不能作为通用规则。

<a id="part-3"></a>

## 3. 用引用绑定理解左值和右值

引用可以先理解为“通过另一个名字访问所绑定的对象”，建立引用本身不是复制对象。

### 3.1 非 const 左值引用 T&

```cpp
int a = 10;

int& r1 = a;    // 正确：绑定左值
// int& r2 = 10; // 错误：不能这样绑定右值
```

`r1` 引用 a。修改 `r1` 就是在修改 a：

```cpp
r1 = 30;
// 此时 a 也是 30
```

### 3.2 右值引用 T&&

```cpp
int&& r3 = 10;   // 正确：绑定临时 int 对象
// int&& r4 = a; // 错误：表达式 a 是左值
```

这里 `&&` 出现在类型声明中，表示右值引用，不是逻辑与运算，也不是“取两次地址”。

在 `int&& r3 = 10;` 这种局部直接绑定中，临时对象的生命周期会延长到该引用的生命周期。不要把它推广成“任何经过引用传递的临时对象都会一直存活”，生命周期延长有具体规则。

### 3.3 const 左值引用 const T&

```cpp
const int& r5 = a;  // 可以绑定左值
const int& r6 = 10; // 也可以绑定右值
```

这也是函数经常通过 `const T&` 接收只读输入的原因之一。

### 3.4 先记住这张绑定表

以下针对这里的普通同类型例子，不展开类型转换和模板推导：

| 引用声明 | 绑定非 const 左值 | 绑定 const 左值 | 绑定同类型非 const 右值 |
|---|---|---|---|
| `T&` | 可以 | 不可以 | 不可以 |
| `const T&` | 可以 | 可以 | 可以 |
| `T&&` | 不可以 | 不可以 | 可以 |

这里说的是类型已经确定的 `T&&`；模板中的转发引用另见第 9 节。

## 4. std::move 为什么能让表达式成为右值

后面的 Buffer 片段假设它提供接收大小的构造函数，以及可用的拷贝、移动构造函数。完整类型定义见第 8 节。

```cpp
Buffer a(100);
```

直接使用 `a`，是左值表达式：

```cpp
a
```

使用 `std::move(a)`，得到的是右值表达式，更精确地说是**将亡值（xvalue）**：

```cpp
std::move(a)
```

但是，这个转换本身：

- 没有创建另一个 Buffer。
- 没有调用移动构造函数。
- 没有转移资源。
- 没有销毁 a。

它仍然关联原来的对象 a，只是改变这次表达式的值类别，让后续操作可以匹配右值引用参数。

可以理解为：

> 这一次使用 a 时，我允许把它交给移动操作。

于是：

```cpp
Buffer b(a);             // 选择拷贝构造
Buffer c(std::move(a));   // 可以选择移动构造
```

实际的资源转移由被选中的移动操作实现，不是由 `std::move` 完成。

注意：这个允许移动的信号，不自动保证业务上适合移动。若其他模块还依赖 a 的旧内容，你仍需先处理这些依赖。

## 5. 左值、纯右值、将亡值是什么关系

现代 C++ 中，三个基本值类别是：

| 名称 | 英文 | 入门理解 | 常见例子 |
|---|---|---|---|
| 左值 | lvalue | 表示具有身份的对象或函数，不属于将亡值 | `a`、`*p`、`values[0]` |
| 纯右值 | prvalue | 产生用于初始化对象或参与计算的值 | `10`、整数相加 `a + b`、`Buffer(100)` |
| 将亡值 | xvalue | 关联有身份的对象，同时可参与右值引用匹配 | `std::move(a)` |

它们还有两种分组：

- **右值（rvalue）= 纯右值 + 将亡值。**
- **泛左值（glvalue）= 左值 + 将亡值。**

“身份”可以先理解成能够确定“具体是哪一个对象或函数”，不是只有一个脱离对象的数值。

所以不能简单地说“右值没有身份”：将亡值是右值，但仍然关联具体对象。也不能说“能定位具体对象就一定是左值”，因为还可能是将亡值。

### 将亡值不是马上就会销毁

```cpp
Buffer a(100);
Buffer&& ref = std::move(a);
```

这只是建立一个引用，没有移动构造新 Buffer，a 也没有因此被销毁。`ref` 和 a 关联的是同一个对象。

“将亡”是术语，不是一个“马上调用析构函数”的命令。

### C++17 的临时对象边界

`Buffer(100)` 是类类型纯右值，但不要机械脑补成“总是先创建临时对象，再调用一次移动构造”：

```cpp
Buffer a = Buffer(100);
```

在 C++17 的这个同类型初始化场景中，会直接构造 a，不需要先构造另一个 Buffer 再移动。这也是为什么不宜用这行代码测试移动构造是否被调用。

初学时先记：**纯右值不等于一定产生额外临时对象和额外移动。**

## 6. 为什么右值引用变量使用起来又是左值

这是理解右值引用与移动语义时最容易混淆的地方。

```cpp
Buffer a(100);
Buffer&& ref = std::move(a);
```

必须分开看两个问题：

| 问题 | 答案 |
|---|---|
| ref 的声明类型是什么？ | `Buffer&&`，右值引用 |
| 直接写出表达式 ref，是什么值类别？ | 左值 |
| 表达式 std::move(ref) 是什么值类别？ | 将亡值，属于右值 |

于是：

```cpp
Buffer b(ref);             // ref 是左值表达式：拷贝构造
Buffer c(std::move(ref));   // 转成将亡值后，可以选择移动构造
```

直观理解是：给引用起名字以后，你可以反复通过这个名字访问对象。语言不会因为它声明为 `&&`，就在每次使用时自动把资源交出去。

### 移动构造中的参数也遵守同样规则

```cpp
#include <string>
#include <utility>

struct Message {
    std::string text;

    Message(Message&& other) noexcept
        : text(std::move(other.text)) {}
};
```

逐层判断：

1. 参数 other 声明为右值引用。
2. 在函数体或成员初始化列表里，表达式 `other` 是左值。
3. 这里的普通成员表达式 `other.text` 也是左值。
4. `std::move(other.text)` 得到将亡值，让 string 的移动构造有机会被选中。

如果改成：

```cpp
// 对比用的初始化写法，不是另一份完整类定义
Message(Message&& other)
    : text(other.text) {}
```

虽然外层函数叫“移动构造函数”，这里的字符串成员却会被拷贝。

**移动构造函数不会自动把所有成员都移动，成员如何初始化仍取决于实际表达式。**

## 7. 把表达式分类与拷贝、移动连起来

一个类可能提供：

```cpp
Buffer(const Buffer& other); // 拷贝构造
Buffer(Buffer&& other);      // 移动构造
```

两种调用的分析过程：

| 调用 | 实参表达式 | 绑定与选择 |
|---|---|---|
| `Buffer b(a)` | a 是左值 | 不能绑定普通 `Buffer&&`；可绑定 `const Buffer&` |
| `Buffer c(std::move(a))` | 将亡值 | 两种引用可能都可绑定；本例中右值引用重载更优 |

要记住的是：

> 先判断表达式的类型和值类别，再看哪些参数可以绑定，最后进行重载选择。

不是“看到 std::move 就不用分析，必然移动”。

### 为什么 std::move 有时仍然复制

如果类没有声明移动构造，但有可用的 const 引用拷贝构造，右值仍可能绑定到拷贝构造的参数。

另一个常见情况是 const：

```cpp
const std::string source = "hello";
std::string target(std::move(source)); // 拷贝，不是通常的 string 移动
```

`std::move` 不会去掉 const。通常的 string 移动构造接收 `std::string&&`，不能通过它修改 const 源对象，因此这里选择拷贝。

也不要把它概括成“移动不可用就一定回退到拷贝”：如果有一个更优匹配的移动构造被显式声明为 `= delete`，重载选择可能选中它并报错。

## 8. 一段可以运行的完整示例

这一节可以直接保存为 `value_categories.cpp` 编译运行。前面的零散片段用于分步讲解，不需要拼在一起。

```cpp
#include <cstddef>
#include <iostream>
#include <utility>
#include <vector>

// 教学示例：只观察引用绑定、拷贝构造和移动构造，
// 不是完整的生产 Buffer API。
struct Buffer {
    std::vector<int> data;

    explicit Buffer(std::size_t size) : data(size) {}

    Buffer(const Buffer& other) : data(other.data) {
        std::cout << "copy\n";
    }

    Buffer(Buffer&& other) : data(std::move(other.data)) {
        std::cout << "move\n";
    }
};

void inspect(Buffer&) {
    std::cout << "lvalue\n";
}

void inspect(Buffer&&) {
    std::cout << "rvalue\n";
}

int main() {
    Buffer a(100);

    inspect(a);              // 左值引用重载
    inspect(Buffer(100));    // 右值引用重载
    inspect(std::move(a));   // 右值引用重载，但 inspect 不移动资源

    Buffer&& ref = std::move(a); // 只建立引用，没有构造新 Buffer
    inspect(ref);                // ref 表达式仍是左值

    Buffer b(ref);             // 拷贝构造
    Buffer c(std::move(ref));   // 移动构造

    return 0;
}
```

预期输出：

```text
lvalue
rvalue
rvalue
lvalue
copy
move
```

Linux/macOS 或相应终端中可运行：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic value_categories.cpp -o value_categories
./value_categories
```

Windows PowerShell 中，编译器已加入 PATH 时可运行：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic value_categories.cpp -o value_categories.exe
.\value_categories.exe
```

实验重点：`inspect(std::move(a))` 只是绑定右值引用参数。inspect 的函数体只打印文本，所以不会转移 a 的资源。直到最后构造 c 时，才真正调用移动构造。

## 9. 常见误区与边界

### 误区一：左值一定在左边，右值一定在右边

错误。`a = b` 中，表达式 a 和 b 都是左值。

### 误区二：左值都可以修改

错误。const 对象的名字也可以是左值表达式，但不能因此修改对象。

### 误区三：右值都没有名字，或者都没有身份

不准确。右值中的将亡值仍然关联具体对象，`std::move(a)` 就关联 a。

### 误区四：std::move 会立即搬走资源

错误。它只是转换表达式，实际是否移动取决于后续选中的操作及其实现。

### 误区五：一旦 std::move(a)，以后 a 就变成右值

错误。值类别针对具体表达式。以后再次直接写 `a`，仍是左值表达式。

如果之前已经真正执行移动，a 的内容可能变化，但这与表达式 a 仍是左值并不矛盾。

### 误区六：右值引用变量直接使用时还是右值

错误。`Buffer&& ref` 中，直接使用名字 ref 得到左值表达式；`std::move(ref)` 才得到将亡值。

### 误区七：移动后的对象一定为空，或者再也不能使用

都不能一概而论。只执行 `std::move(a)` 未必移动；真正移动后的状态则取决于类型契约。

标准库类型通常规定移动后有效但状态未指定，部分类型还有更明确的保证。不能对“状态未指定”的内容作额外假设；调用有前置条件的成员前，仍需满足条件。自定义类应明确自己的移动后状态。

### 误区八：所有 T&& 都只能接收右值

还要看是否处于模板推导场景：

```cpp
template<class T>
void process(T&& value);
```

这里由调用参数推导 T 的形式可以是转发引用，既能接收左值，也能接收右值。它涉及引用折叠和 `std::forward`，属于下一阶段内容。

而 `Buffer(Buffer&& other)` 中的 Buffer 已经是确定类型，是普通右值引用，不是转发引用。

## 10. 判断步骤与速查表

遇到一段代码时，按这个顺序分析：

1. **先找表达式。** 不要只盯着变量声明中的 `&` 或 `&&`。
2. **看类型和 const。** 它是 Buffer、const Buffer，还是其他类型？
3. **判断值类别。** 是对象名字、计算结果，还是 `std::move(...)`？
4. **判断参数能否绑定。** 分清 `T&`、`const T&`、普通 `T&&`。
5. **最后看实际选中的操作。** 被调用的是拷贝、移动，还是仅接收一个引用？

假设 a、b 是 int，p 是有效 int 指针，values 是 int 数组，buffer 是非 const Buffer：

| 表达式 | 值类别 | 关键原因 |
|---|---|---|
| `a` | 左值 | 表示已有对象 |
| `b`，即使出现在 `a = b` 右侧 | 左值 | 位置不改变表达式分类 |
| `*p` | 左值 | 表示指针指向的对象 |
| `values[0]` | 左值 | 表示数组元素 |
| `10` | 纯右值 | 提供一个 int 值 |
| `a + b` | 纯右值 | 内置整数加法产生结果 |
| `Buffer(100)` | 纯右值 | 同类型直接初始化不必额外移动 |
| `std::move(buffer)` | 将亡值 | 仍关联 buffer，可匹配右值引用 |
| `ref`，其中声明为 `Buffer&& ref` | 左值 | 直接使用有名字的引用 |
| `std::move(ref)` | 将亡值 | 对这次表达式作转换 |

以上表格不能机械套到所有重载运算符或自定义代理类型上。复杂表达式仍要看实际声明和语言规则。

## 11. 常见问题与解答

以下问答用于快速定位疑惑，每个问题后直接给出结论和原因。

### a = b 中，b 在等号右边，为什么仍是左值？

因为表达式 b 表示已有对象，表达式分类不由等号位置决定。

### const int n = 10 中，表达式 n 是不是左值？

是左值，但不是可修改左值。const 限定和值类别需要分别判断。

### int* p = &a 中，表达式 *p 是什么值类别？

是左值，它表示指针所指向的具体对象。

### Buffer&& ref = std::move(a) 是否已经调用移动构造？

没有。这里只建立引用，没有构造新的 Buffer，也没有自动转移资源。

### 声明为 Buffer&& 的 ref，直接使用时是什么值类别？

表达式 ref 是左值。引用的声明类型和值类别要分别判断。

### Buffer b(ref) 与 Buffer c(std::move(ref)) 为什么可能调用不同构造函数？

ref 是左值，不能绑定普通 `Buffer&&`；`std::move(ref)` 是将亡值，可匹配移动构造。在本文提供的两个构造函数都可用时，分别选择拷贝和移动。

### std::move(a) 会把变量 a 永久变成右值吗？

不会。以后直接写 a，仍是左值表达式；实际内容是否变化另看是否执行了移动。

### 函数接收 Buffer&&，但函数体只打印日志，调用它是否一定转移资源？

不一定。右值引用绑定不等于资源转移，具体行为取决于函数实现。

<a id="part-12"></a>

## 12. 核心概念总结

左值、右值与移动语义的关系可以概括为：

> 左值和右值是表达式的值类别，不是由它在等号哪一边决定。表达式 a、*p 和数组下标通常是左值，整数常量和整数加法结果是纯右值。右值还包括将亡值，例如 std::move(a)。std::move 本身不移动资源，只把表达式转换为可参与移动操作的类别。右值引用参数虽然声明为 T&&，但在函数内部直接使用参数名仍是左值，因此移动成员时通常还需要 std::move。

下面这组代码集中展示了几个关键区别：

```cpp
Buffer a(100);

a;                         // 左值表达式
Buffer(100);               // 纯右值表达式
std::move(a);              // 将亡值表达式，本身不移动

Buffer&& ref = std::move(a); // 只建立引用

ref;                       // 左值表达式
std::move(ref);             // 将亡值表达式
```

最后记住三层区别：**声明类型 → 表达式值类别 → 实际选中的操作。**
